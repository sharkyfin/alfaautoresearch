# AutoResearch: контекст, признаки и временная проверка

По умолчанию агент по-прежнему работает до 900 секунд на задачу. Дополнительные
проверки расходуют этот же бюджет и учитываются при резервировании времени на
подтверждение и финальное обучение. CatBoost в поиске отсутствует.

## Контекст Qwen

В запрос попадают колонки с наиболее полезными свидетельствами:

- важность у уже обученных моделей, включая связь производных признаков с
  исходными колонками;
- входы принятых формул;
- агрегированная связь величины ошибок с числовыми значениями, пропусками и
  категориями на собственной валидации;
- пропуски и различия распределений train/test.

Оставшееся место используется для просмотра всей схемы. Словарь описаний
выбирается по тем же именам и в том же порядке: важная колонка после 200-й
позиции больше не теряет описание из-за прежнего `head(60)`.

Для ограничения стоимости анализа: связи с ошибками оцениваются максимум по
2048 строкам и 80 колонкам; дополнительные профили за пределами первых 200
строятся максимум для 256 колонок по выборкам до 512 строк. Выбранная моделью
важная колонка может получить профиль отдельно. В API передаются агрегаты,
имена и описания, без исходных строк и идентификаторов объектов. Сам запрос
ограничен 10 000 байт; при сокращении первыми удаляются данные меньшего приоритета.

Эти связи помогают сформулировать гипотезы, но сами по себе не доказывают
полезность признака. Её проверяет обучение и исходная метрика.

## Изолированная проверка признаков

Если гипотеза меняет признаки, исполнитель фиксирует семейство модели,
гиперпараметры, преобразование целевой переменной, разбиение и seed текущего
победителя. Одновременные запрошенные изменения модели игнорируются после
проверки допустимости запроса; это отражается в `ignored_model_overrides`.
Изменения модели и параметров остаются доступны отдельными экспериментами.

Одна гипотеза может изменить не более четырёх формул/legacy-операций. Общий
лимит принятых формул остаётся 16. Добавление, изменение и явная замена списков
через `feature_mode=replace` поддерживаются в этих пределах.

После улучшения группы из нескольких изменений агент выполняет до трёх
абляций: поочерёдно отменяет одно изменение и повторяет обучение с теми же
настройками. Если удаляется формула, удаляются и зависящие от неё формулы.
Уже измеренный исходный рецепт повторно не обучается. Каждая следующая абляция
строится от текущего лучшего варианта, поэтому удалённые признаки не возвращаются
случайно в следующем опыте.

Изменение можно отменить без существенного ухудшения: допуск равен
`max(1e-5, abs(utility) * 0.0005)`. При этом итог обязан сохранять существенный
выигрыш относительно исходного родителя. Это практическое правило выбора,
а не проверка статистической значимости. При нехватке времени или лимита
экспериментов сохраняется лучший уже проверенный прогноз.

`experiments.jsonl` содержит `feature_trial`, исходного родителя и результат;
абляции помечены `origin=feature-ablation`. Обратная связь о последней гипотезе
Qwen и последней абляции сохраняется при сокращении следующего запроса.

## Временные задачи

До обучения фиксируются основное последнее окно и до двух предыдущих
непересекающихся окон. Пример для равномерных временных меток:

| Проверка | Обучение | Валидация |
|---|---|---|
| Основная | первые 80% | последние 20% |
| Подтверждение 1 | первые 60% | 60–80% |
| Подтверждение 2 | первые 40% | 40–60% |

Для каждого запуска используются только более ранние наблюдения. Одинаковые
временные метки не разделяются между окнами; заданный `gap_rows` применяется
перед каждым окном и не уменьшается. Если истории недостаточно, дополнительных
окон будет меньше. Для обычных IID/group-задач остаётся одно дополнительное
разбиение.

Финалисты сравниваются на общих успешно выполненных контрольных окнах по
`mean(utility) - 0.25 * std(utility)` с учётом основной проверки. Частично
выполненное дополнительное окно не даёт одному финалисту преимущества в
сравнении. Ансамбль и поправки вероятностей должны улучшать каждое общее
контрольное окно, а не только среднюю оценку.

План и фактические метрики записываются в `confirmation_plan` и
`confirmation_metrics` файла `summary.json`. Число дополнительных проверок
может быть ограничено оставшимся временем. Временная проверка не добавляет
поддержку произвольных задач forecasting: агент по-прежнему работает с
предоставленными табличными train/test.

## Проверка

```sh
.venv/bin/python -m pytest tests/test_research_improvements.py -q
.venv/bin/python scripts/check_all.py
.venv/bin/python scripts/package_submission.py
.venv/bin/python scripts/verify_zip.py
.venv/bin/python scripts/audit_platform.py
```

Новые проверки включают реальные worker-обучения линейной модели с известным
взаимодействием, удаление лишнего признака, контроль параметров, временные окна,
финальный refit и валидный CSV. HTTP-прокси в проверке архива — локальная заглушка,
а не настоящая LLM. Это подтверждает выполнение протокола, а не прирост качества
на публичных или скрытых задачах хакатона.
