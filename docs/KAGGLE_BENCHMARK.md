# Быстрые локальные проверки на Kaggle-данных

Этот стенд оценивает качество агента на реальных данных без отправок в Boosters
или Kaggle. Запускается тот же runtime, который лежит в `submission.zip`:
бенчмарк извлекает и проверяет исходники по SHA256, затем делает неизменяемую
копию для всей серии. Формат task.md, CSV, выбор подхода, AutoResearch,
подтверждение и финальный refit сохраняются.

## Наборы и метрики

| Набор | Строк | Задача | Основная метрика |
|---|---:|---|---|
| [California Housing](https://www.kaggle.com/datasets/camnugent/california-housing-prices) | 20 640 | Регрессия, жильё и география | RMSE, меньше лучше |
| [Adult Income](https://www.kaggle.com/datasets/uciml/adult-census-income) | 32 561 | Бинарная классификация, категории и пропуски | Macro F1, больше лучше |
| [Dry Beans](https://www.kaggle.com/datasets/muratkokludataset/dry-bean-dataset) | 13 611 | Семь классов, геометрические признаки | Macro F1, больше лучше |

Это независимые задачи для разработки. Их результаты не являются баллами
лидерборда хакатона; официальный бейзлайн на его скрытом тесте неизвестен.
Сырые значения RMSE и F1 не усредняются между задачами.

## Три режима

- `lightgbm`: фиксированный локальный ориентир без AutoResearch — одна модель
  LightGBM, собственный holdout, подтверждение и refit. Для короткого бюджета
  задано 500 итераций, для бюджета от 180 секунд — 1800; работает early stopping.
- `deterministic`: полный текущий агент без обращений к Qwen.
- `live-agent`: тот же агент с организаторским Qwen, максимум два обращения
  на задачу по умолчанию.

У режимов совпадают исходные данные, внешнее разбиение, seed, лимит времени и
число потоков. Фактическое время может различаться: фиксированная модель обычно
завершается раньше. В коротком прогоне у портфеля агента есть меньше итераций,
чем при обычных 900 секундах. Для релизного вывода нужен более долгий замер.
Поле `internal_metric` — метрика выбранного одиночного кандидата на внутреннем
holdout; итоговый CSV может дополнительно использовать подтверждённый ансамбль.
Качество результата сравнивается по `external_metric`.

## Отделение ответов

Данные разделяются один раз на 60/20/20. Группы точных дубликатов признаков
сохраняются вместе; классификация по возможности стратифицируется по классам.

В обычном прогоне агент получает только 60% строк с ответами и признаки
следующих 20% без ответов. Внутреннюю валидацию он строит внутри этих 60%.
Внешние ответы лежат в соседней папке `sealed`, не передаются через CLI,
task.md, словарь или контекст Qwen. Оценщик читает их после завершения процесса
агента. Следующие изменения кода можно выбирать по этой development-оценке.

Последние 20% не входят даже в признаки обычной проверки. `--final` обучает
выбранную версию на первых 80% и оценивает её на оставленных 20%. Используйте
эту проверку после выбора версии и режима, иначе финальная выборка постепенно
тоже превратится в development-набор. CLI требует один выбранный режим для
такой проверки.

В отчёт входят SHA256 архива данных, разбиения, исходников и входных файлов,
внешняя и внутренняя метрики, время, реальный запуск Qwen и его эксперименты.
`constant_fallback`, `timeout` и ошибки учитываются явно: корректный CSV с
константой не выдаётся за успешный ML-поиск.

## Запуск

Из корня репозитория, в существующем Python 3.12 окружении с утверждёнными
версиями библиотек:

```sh
.venv/bin/python scripts/download_kaggle.py
.venv/bin/python scripts/benchmark_kaggle.py
```

Первый запуск кэширует три публичных ZIP, всего около 5,6 МБ. Упаковка данных
не исполняется: CSV/ARFF читаются напрямую из архива. Вход в Kaggle для этих
публичных загрузок не используется. Команды датасетов описаны также в
[официальной документации Kaggle](https://github.com/Kaggle/kaggle-cli/blob/main/docs/datasets.md).

По умолчанию: три набора, три режима, один seed, 90 секунд на задачу — до
13,5 минут модельного времени плюс подготовка данных. Последовательные запуски
с восемью потоками делают сравнение времени воспроизводимее.

Быстрая проверка изменения модели или поиска без ожидания API:

```sh
.venv/bin/python scripts/benchmark_kaggle.py --cases adult_income --modes lightgbm,deterministic --budget 90 --report reports/kaggle-adult.json
```

Сравнение на нескольких seeds с большим бюджетом:

```sh
.venv/bin/python scripts/benchmark_kaggle.py --modes deterministic,live-agent --budget 300 --seeds 42,53 --report reports/kaggle-confirmation.json
```

Для проверки именно Qwen начните с одного набора и 300 секунд. Текущий клиент
запрашивает компактный JSON без внутреннего рассуждения, чтобы reasoning не
поглотил лимит ответа. На ожидание API выделяется до четверти оставшегося
поискового бюджета, максимум 40 секунд; соединение ограничено пятью секундами.
Если `qwen_fits = 0`, качество Qwen-гипотез ещё не проверено. Причины тайм-аутов,
задержки, `finish_reason` и reasoning-токены записываются в `qwen_events`.

Финальная проверка уже выбранного режима:

```sh
.venv/bin/python scripts/benchmark_kaggle.py --final --modes live-agent --budget 300 --report reports/kaggle-final.json
```

Для полностью локального запуска без расходов на LLM:

```sh
.venv/bin/python scripts/benchmark_kaggle.py --modes lightgbm,deterministic
```

Ключ Qwen берётся из игнорируемого `.env.organizer.local` или переменных
окружения. Он не копируется в snapshot и не передаётся ML-workers. Live-режим
требует доступа к официальному прокси. Тайм-ауты и отсутствие реально обученных
Qwen-гипотез видны в полях `qwen_calls`, `qwen_fits` и `qwen_events`.

Основные файлы: `reports/kaggle-benchmark.json` и его Markdown-таблица;
полные логи, CSV и замороженный runtime — в новом `runs/kaggle-benchmark-*`.
Следующий запуск создаёт отдельную папку. Старый архив можно сравнить на тех же
данных через `--zip /path/to/submission.zip`, если он использует текущий плоский
формат с контрольными суммами исходников.

Первый прогон до исправления клиента описан в
[reports/KAGGLE_FINDINGS.md](../reports/KAGGLE_FINDINGS.md).
Изменения агента и контрольное сравнение итогового ZIP:
[docs/QUALITY_UPDATE.md](QUALITY_UPDATE.md).

## Как переносить в Kaggle Notebooks

Сначала используйте локальный стенд: это проще для коротких циклов изменения
кода и чтения логов. При необходимости тот же репозиторий, `submission.zip` и
три исходных архива можно перенести в приватный Notebook, указав `--raw-dir`
на папку с архивами. Версии библиотек должны соответствовать требованиям;
установка для разработки выполняется до запуска агента, вне конкурсного
runtime. Ключи задаются через Kaggle Secrets и переменные окружения, не через
ячейки с литералами ключей.

Бенчмарк, его данные и настройки не входят в загружаемый агент. Новые признаки
и стратегии должны оставаться универсальными: названия этих датасетов не
добавляются в ветвления runtime.
