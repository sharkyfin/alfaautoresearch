# Проверка требований Boosters

Источник контракта: инструкция организаторов, повторно предоставленная пользователем.
Актуальные результаты проверок: `reports/platform-compliance.json`,
`reports/test-state.json`, `reports/zip-verification.json`.

| Требование | Реализация и проверка |
|---|---|
| ZIP до 100 МБ, все файлы в корне | Проверяются размер, отсутствие папок, дубликатов имён и посторонних расширений. В архив входят только собственные `.py` и официальный `requirements.txt`. |
| Корневой `solution.py` | Bootstrap восстанавливает собственный пакет в `/tmp`, проверяет SHA256 модулей и запускает точку входа. Создание промежуточных папок в `/tmp` разрешено контрактом. |
| Официальный список зависимостей | `requirements.txt` побайтово совпадает с предоставленным файлом из папки организаторов; импорты проверяются по разрешённому набору. |
| Без установки пакетов во время решения | В загружаемом Python нет `pip install`, загрузки весов или сторонних `.whl`. Установка для разработки выполняется вне runtime. |
| `python3 solution.py task.md` | Архив проверяется именно этой командой из новой папки задачи после копирования только корневых `.py` и `requirements.txt`. |
| `submission.csv` рядом с `task.md` | Путь зафиксирован. Примеры `predictions.csv` в тексте не перенаправляют вывод. CSV записывается в UTF-8, без индекса, с порядком колонок и ID из sample. |
| Чтение материалов задачи | Метрика, таргет, роли и типы признаков определяются из описания, словаря и схемы CSV. Относительные пути поддерживаются в inline code, Markdown-ссылках и обычном тексте. |
| Автономный цикл AutoResearch | После двух стартовых моделей Qwen получает описание данных и измеренные результаты. Рецепт проверяется, генерируется код, worker обучает модель, независимый judge считает метрику; результат возвращается в последующий контекст. |
| Только предоставленные данные и официальный LLM | Runtime читает материалы задачи, обращается к прокси из `OPENAI_BASE_URL` с `OPENAI_API_KEY`; имя модели берётся из необязательного `OPENAI_MODEL` или документированного значения Qwen. Ключи и OpenRouter не входят в ZIP. |
| 8 CPU, 32 ГБ RAM | Параллелизм библиотек и job-настройки ограничены 8 потоками; worker имеет лимит 24 ГиБ и контроль памяти. Фактический общий предел контейнера устанавливает платформа. |
| До 3 часов на задачу | Бюджет стандартного запуска — 10 500 секунд (2 ч 55 мин), с запасом до лимита платформы. Worker-вызовы ограничены оставшимся временем; предусмотрено завершение и сохранение ранее полученного ответа при остановке. |
| Один код для разных задач | Проверяются регрессия, бинарная и многоклассовая классификация с разными метками и метриками; в runtime нет условий по именам публичных датасетов. |
| Три отправки в день | Это ограничение платформы. Проверки выполняются локально, автоматической отправки и расхода сабмитов нет. |

## Что исправлено при аудите

1. Итоговый CSV всегда сохраняется под требуемым именем в папке задачи.
2. Разбор входных путей поддерживает Markdown-ссылки и обычный текст; URL из
   справочных материалов не принимаются за абсолютные локальные пути.
3. Первая исследовательская итерация выполняется раньше, чтобы ускоренный бюджет
   не уходил целиком на стартовый перебор моделей.
4. При сокращении контекста сохраняется обратная связь о последнем эксперименте Qwen.
5. Кэш Matplotlib у workers направлен в их рабочую папку.
6. Контекст выбирает колонки по свидетельствам, включая важные колонки за пределами
   начала схемы; гипотезы признаков проверяются отдельно от изменения модели.
7. Успешные группы признаков проходят ограниченные абляции. Временные финалисты
   проверяются на отдельных предыдущих окнах с соблюдением `gap_rows`.
   Подробный протокол: [AUTORESEARCH.md](AUTORESEARCH.md).
8. Текстовая проекция TF-IDF/SVD обучается с нуля внутри фолда, без внешних весов.
9. Optuna TPE использует разрешённую версию библиотеки и реальные метрики.
10. Финальный выбор требует всех запланированных фолдов с сохранением групп и времени.

## Воспроизведение

```sh
.venv/bin/python scripts/check_all.py
.venv/bin/python scripts/package_submission.py
.venv/bin/python scripts/verify_zip.py
.venv/bin/python scripts/audit_platform.py
```

`verify_zip.py` проверяет сохранение результата при SIGTERM. `audit_platform.py`
проверяет полное завершение трёх новых задач, включая временную регрессию,
реальные worker-обучения, генерацию
формул, финальный refit и CSV через плоский ZIP. Его локальный HTTP-прокси отвечает
контролируемой JSON-гипотезой и не является настоящей LLM. Настоящий организаторский
Qwen проверяется отдельным smoke-тестом в `reports/platform-qwen-live.json`;
его `runtime_code_sha256` указывает версию этой проверки.

## Границы проверки

Образ Docker организаторов локально недоступен. Текущий архив исполняется в
Python 3.12 на macOS; старые Linux-отчёты относятся к указанным в них архивам.
Проверка не доказывает работу внутренней очереди, сетевого маршрута и скоринга Boosters.

Поддержана одна целевая переменная для табличной регрессии и классификации.
Несколько таргетов, multilabel/ranking и произвольные неизвестные метрики не
покрыты полностью. Поэтому формулировка «другие задачи машинного обучения» не
означает подтверждённую поддержку любой возможной приватной постановки.
Подробные границы перечислены в `reports/SUPPORTED_TASKS.md`.
