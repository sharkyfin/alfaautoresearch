# Текстовые признаки, адаптивный поиск и проверка финалистов

Релиз добавляет три изменения. Стандартный запуск остаётся
`python3 solution.py task.md`, бюджет — 900 секунд на задачу, до 8 CPU.
Предобученные веса, внешние данные и дополнительные API не используются.

## TF-IDF → SVD → нормировка

Для бустингов и ExtraTrees текстовые колонки автоматически получают плотные
векторные признаки. Словарь TF-IDF и SVD обучаются только на обучающей части
текущего фолда, затем применяются к валидации и тесту. Линейная модель сохраняет
свою разреженную TF-IDF-ветку.

- До двух текстовых колонок, 12 000 терминов на колонку.
- До 20 000 обучающих документов для подбора словаря и проекции.
- По умолчанию 64 компоненты; фактическая размерность ограничена размером данных.
- TPE может проверить 0, 32, 64 или 128 компонент; 0 отключает проекцию.
- Применение выполняется пакетами по 2 048 строк с результатом float32.
- Векторы после SVD нормируются, чтобы новые слова не меняли масштаб общих тем.
- Пустой словарь не останавливает решение; остаются остальные признаки.
- Явные типы `text` и `free_text` в словаре поддерживаются и для коротких строк.

Это LSA на данных задачи. Метод не получает семантических знаний из внешней
предобученной модели. [TruncatedSVD в scikit-learn 1.5.2](https://scikit-learn.org/1.5/modules/generated/sklearn.decomposition.TruncatedSVD.html).

## Поиск моделей и параметров

После стартового портфеля и первых семантических экспериментов включается Optuna
TPE. Исследуются параметры двух лучших измеренных семейств; второе семейство
получает каждую третью попытку. Сохраняются его собственные признаки и target
transform, поэтому подбор другой модели не замораживается ошибочно на текущем
общем чемпионе.

TPE получает реальные метрики выполненных обучений. Исследования разделяются
по семейству, набору формул, преобразованию цели и лимиту итераций. Невыполненная
или отклонённая попытка не записывается как успешное наблюдение. Всё хранится
в памяти, без сетевого хранилища.

Вместо остановки после десяти неудачных попыток допускаются до 48 шагов
исследования, до 60 поисковых экспериментов в обычном CLI. При 18 попытках без
улучшения и как минимум 12 завершённых TPE-обучениях поиск может завершиться
раньше. При нехватке времени продолжают действовать измеренная стоимость
обучений, резерв на подтверждение и refit, общий дедлайн и безопасный CSV.

Optuna 4.2.1 уже включена в официальный requirements; в локальное окружение
добавлена та же версия. Официальный загружаемый файл зависимостей не меняется.
В LightGBM для `subsample < 1` включается частота subsample, чтобы этот параметр
действительно участвовал в обучении.

## Финальный выбор на трёх фолдах

Для обычной задачи до начала поиска фиксируются основной валидационный фолд
примерно на трети данных и ещё два непересекающихся фолда. Поиск использует только
первый. Лучшие три кандидата затем обучаются и оцениваются на остальных двух.
В каждом запуске заново обучается вся предобработка, включая текстовую проекцию.

Классификация стратифицируется по возможности, группы сущностей и точные
дубликаты сохраняются вместе. Единичные классы остаются в обучении каждого
фолда. При недостатке наблюдений допустимо меньше проверок. Временные задачи
используют прежние последовательные окна с `gap_rows` и без перемешивания.

Для окончательного сравнения кандидат должен успешно завершить все
запланированные фолды. Используется `mean(utility) - 0.25 * std(utility)`.
Если полная проверка не выполнена ни у одного кандидата, сохраняется результат
поискового holdout, а fallback явно отмечается в отчёте.

Веса ансамбля выбираются на поисковом фолде и должны подтвердить улучшение
на каждом контрольном фолде. Финальное обучение использует все известные ответы;
для числа итераций берётся медиана измеренных значений по фолдам.

В `summary.json` добавлены `adaptive_search` и `cross_validation`: число TPE-проб,
семейства, фолдовые метрики, среднее, разброс и фактическая полнота проверки.

## Проверка

```sh
.venv/bin/python scripts/check_all.py
.venv/bin/python scripts/package_submission.py
.venv/bin/python scripts/verify_zip.py
.venv/bin/python scripts/audit_platform.py
.venv/bin/python scripts/download_kaggle.py --cases sms_spam
.venv/bin/python scripts/run_kaggle_full.py --case sms_spam --report reports/text-cv-sms-after.json
```

Новые тесты проверяют словарь без валидационных слов, поведение на пустом и
маленьком словаре, перенос текстового сигнала на новые сообщения, отсутствие
пересечений фолдов и групп, сохранение редких классов, отказ от переобученного
победителя одного holdout, неполные проверки и передачу метрик в воспроизводимый TPE.

## Измеренные результаты

257 тестов прошли на неизменном runtime. Проведены парные проверки на пяти
Kaggle-датасетах: [все метрики и время](../reports/text-cv-comparison.md).
На бетоне RMSE снизился на 10,02%, на Adult Income Macro F1 вырос на 1,018 п.п.,
на Dry Beans — на 0,362 п.п. Изменение SMS Spam небольшое: +0,013 п.п.
На California Housing RMSE вырос на 1,72%. Это измерения на одном разбиении
каждой задачи; они не гарантируют улучшение на скрытых данных хакатона.

Полные запуски ZIP с реальным Qwen на бетоне и SMS завершились за 70,7 и
120,6 секунды соответственно при неизменном лимите 900 секунд. SMS-финалист
использует 128 SVD-компонент и признаки, предложенные Qwen. Компоненты изменения
проверялись совместно; отдельный вклад SVD в эти внешние метрики не выделен.
